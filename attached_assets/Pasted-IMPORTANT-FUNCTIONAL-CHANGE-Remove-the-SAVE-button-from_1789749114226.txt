IMPORTANT FUNCTIONAL CHANGE:

Remove the SAVE button from the Counter screen.

The Tasbeeh Counter should automatically persist the current count.

A user should NEVER need to press Save to preserve their current count.

========================================
AUTOMATIC COUNT PERSISTENCE
========================================

Every count increment must be persisted locally.

If the user:

- closes the app
- backgrounds the app
- switches to another app
- the app is restarted
- the phone restarts
- the app is reopened later

the latest saved count must be restored.

Example:

User has:

047

User closes the app.

User reopens the app.

The Counter must still show:

047

If they counted to:

048

and immediately close the app, the latest reliably persisted count should be restored when reopening.

Do not require the user to press any Save button.

========================================
REMOVE SAVE BUTTON
========================================

Remove the SAVE button completely from the Counter screen.

The bottom action area should now contain only:

RESET

Redesign the area so RESET looks intentional rather than leaving an empty space where SAVE used to be.

RESET remains clearly visible and accessible.

========================================
AUTO-SAVE SETTING
========================================

The current Settings screen contains:

Auto-save

Since automatic persistence is now a fundamental requirement rather than an optional feature, REMOVE the Auto-save setting.

There should be no setting that allows the user to accidentally disable persistence of their count.

The app should always automatically save the current count.

========================================
PERSISTENCE REQUIREMENT
========================================

Use the existing local/offline storage architecture.

Do NOT add:

- backend
- account
- login
- cloud sync
- database
- network dependency

The app remains completely local/offline.

Persist at minimum:

- current count for each Dhikr
- selected Dhikr
- target information
- required existing History/Stats data
- existing Settings

Do not lose existing user data.

========================================
PERFORMANCE
========================================

Do not implement persistence in a way that causes visible lag on every tap.

The UI must remain immediately responsive.

Use the simplest reliable persistence strategy available in the existing architecture.

The critical requirement is:

COUNTING MUST FEEL INSTANT + COUNT MUST SURVIVE APP CLOSURE.

If you use debounced/batched persistence for performance, make sure there is an additional persistence safety mechanism when the app is backgrounded/unmounted so that a recently changed count is not lost.

========================================
RESET
========================================

RESET should continue to work exactly as before.

When the user resets:

- current count becomes 0
- reset state is persisted automatically
- reopening the app shows 0

Reset must also re-arm target completion behavior as currently implemented.

========================================
TARGET BEHAVIOR
========================================

Do not change:

- target logic
- Stop counting at target
- milestone behavior
- target completion sound
- target completion haptic
- target completion animation

Only change how the count is persisted.

========================================
HISTORY
========================================

Do not remove existing History functionality.

A count should still be represented correctly in History according to the existing History architecture.

Removing the Save button must NOT cause History to stop working.

If the current History implementation uses Save as a session boundary, refactor that behavior appropriately so that removing the UI Save button does not corrupt or lose History data.

Do NOT delete existing History.

========================================
COUNTER UI
========================================

Remove:

SAVE

Keep:

RESET

The Counter screen should become visually simpler.

The physical Tasbeeh remains the primary interaction.
