FEATURES TO IMPLEMENT

1. PER-DHIKR TARGETS
- Each Dhikr must have its own target.
- Do NOT automatically assign a default target.
- The user must choose the target for each Dhikr.
- Provide preset options:
  - 33
  - 99
  - 100
- Also provide a Custom target option.
- Save the selected target locally for each Dhikr.
- If a Dhikr has no target selected yet, show an appropriate "Set Target" state rather than assuming a target.

2. TARGET PROGRESS
- Show the current count.
- Show the selected target.
- Show clear progress toward the target.
- The progress indicator must work correctly across different phone screen sizes.
- Fix the existing progress-bar sizing bug.

3. TARGET COMPLETION
When the user reaches the exact selected target:
- Play a short, pleasant completion "ting" / chime.
- If vibration is enabled, provide haptic feedback.
- Show a subtle visual completion indication.
- Do not show an intrusive popup.
- Trigger the completion effect only once when the target is reached.
- If the user continues counting past the target, do not repeatedly trigger the completion effect.
- Resetting the counter should allow the completion effect to trigger again when the target is reached again.

4. MILESTONE FEEDBACK
Provide subtle feedback when the count reaches:
- 33
- 99
- 100

This should happen even when the selected target is higher.
For example, if the target is 500, the user should still receive milestone feedback at 33, 99 and 100.

If a milestone is also the selected target, do NOT trigger two separate effects. Use the target-completion effect instead.

5. STOP COUNTING AT TARGET
Add a new Settings option:
"Stop counting at target"

Default: OFF.

When OFF:
- The user can continue counting beyond the target.

When ON:
- The counter stops accepting additional counts after the target is reached.

6. COUNTER INTERACTION
- The physical-looking metallic button remains the primary and only counting control.
- Pressing it increments the count.
- Preserve the existing haptic feedback, tap sound and animation settings.
- Preserve the existing button press/spring behavior and LCD number synchronization.
- Remove the confusing invisible reset tap-zone on the counter/dial.
- The visible Reset button remains the reset control.

7. HISTORY AND STATS
Fix the existing misleading Stats values.

Stats must represent:
- Today = actual count recorded today
- This Week = actual count recorded during the current week
- Total = actual all-time count

Keep this completely offline/local.

Use the simplest reliable local data structure needed to track dates/counts. Do not unnecessarily store every individual tap if session-based or daily aggregate storage is sufficient.

Preserve the existing History functionality unless a change is required to make the new statistics accurate.

8. EXISTING DHIKR LIBRARY
Preserve all existing Dhikrs and their separate counts.

Targets must also remain separate for each Dhikr.

Switching between Dhikrs must not lose or mix counts or targets.

9. EXISTING SETTINGS
Preserve:
- Vibration
- Sound
- Counter animation
- Auto-save
- Dark/light theme

Add only the new "Stop counting at target" setting described above.

10. DATA SAFETY
Existing users' saved data must not be lost when the app is updated.

Existing saved counts, history and settings must continue working after adding the new data fields.

11. UI

For this implementation, focus on functionality and correctness.

Later we will do a separate visual-design phase involving:
